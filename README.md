# DRMリンク拾いツール

経路を地図上で指定し、通過する DRM リンク・ノード番号を Excel に出力する社内ツール。
配布場所（全国共有フォルダ）：`\\zlcb005\09_横連携【一時保存】\00_部門共通\04.全国情報共有フォルダ\20_DRM拾いツール\10_リンク拾いツール`

オーナー：@hiroharada　／　改修は全国の社員どなたでも歓迎です。

## 絶対に守ること
- **このリポジトリは Public（全世界に公開）。DRM・JTMA 等のデータ、Excel 出力結果、データが写ったスクリーンショットは絶対に上げない。**
  一度上げると、取り消しても履歴や他人のコピーに残り、回収できません。
- `.gitignore`（`_cache/`・`_利用ログ/`・`*.json`・`*.csv`・`*.xlsx` 等を除外）を消したり緩めたりしない。
- SQL Server（JARTIC・トラカン）へのアクセスは読み取りのみ。パスワード等をコードに書かない（Windows 認証を使う）。

## main に入れると全国に自動で反映されます
1. `main` に push（または Pull Request を取り込み）すると、15 分以内に全国共有フォルダへ自動反映される
2. 利用者は次に `起動.bat` を実行したときから新しい版を使う（画面は Ctrl+F5 で更新）
3. 反映前に自動チェックを行い、次の場合は反映しない
   - Python の文法エラー
   - データらしいファイル（`.json` `.csv` `.xlsx` `.pickle` 等、または 5MB 超）が含まれる
4. 不具合が出たら、GitHub 上で原因のコミットを Revert（取り消し）すれば、同様に自動で元に戻る

## 改修のしかた
**必要なもの**：GitHub アカウント（無料）だけ。招待は不要です。

**かんたんな方法（ブラウザだけ）**
1. 直したいファイルを開いて鉛筆アイコン（Edit）を押す（初回は自分用のコピー＝Fork が自動で作られる）
2. 修正して「Commit changes」→「Propose changes」→「Create pull request」
3. 何を・なぜ直したかを書いて送る。オーナーが確認して Merge すると、15 分以内に全国へ反映される

よく改修する人は、オーナーに GitHub アカウント名を伝えて Collaborator に招待してもらうと、確認なしで main を直接更新できます（その場合は上の 3 で直接 main に commit）。

**本格的に直す方法**
1. 自分の PC に clone し、ブランチを切って修正する（共有フォルダ上で直接作業しない）
2. 動作確認：DRM データと変換済みキャッシュは共有フォルダのものを参照して起動
   ```
   python -X utf8 "30_ツール本体（触らない）\server.py" "\\zlcb005\09_横連携【一時保存】\00_部門共通\04.全国情報共有フォルダ\20_DRM拾いツール\DRMコピー_こっちを使う" --shared-cache="\\zlcb005\09_横連携【一時保存】\00_部門共通\04.全国情報共有フォルダ\20_DRM拾いツール\10_リンク拾いツール\30_ツール本体（触らない）\_cache" --port=8766 --no-usage
   ```
   （`--port` は利用者の 8765 と被らない番号に。`--no-usage` で利用ログに記録しない）
3. main に取り込む（push または Pull Request）

**お願い**
- 1 回の commit / Pull Request には 1 つの改修だけを入れ、何を・なぜ直したかを書く
- 動作確認したこと（どの経路・どの版で試したか）を書く
- 利用者向けの使い方や出力ルールを変えたら、`20_使い方と出力ルール（見なくても良い）.txt` と index.html の `OUTPUT_RULES`（Excel の「出力ルール」シート）も直す

| `20_使い方と出力ルール（見なくても良い）.txt` | 利用者向け説明書 |
